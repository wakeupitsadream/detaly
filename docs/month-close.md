# Деньги под контролем: закрытие месяца, акт пункта выдачи, возвраты Rossko

Шаг 7 порядка работ (docs/PLAN.md, дорожная карта r10 «Деньги под контролем»). Цель: раз в месяц за 15 минут увидеть, сколько денег пришло по чекам, сколько из них осталось после закупки, что подписать с пунктом выдачи, совпадает ли база с ЮKassa и какие деньги от Rossko — не доход. И не терять детали, которые надо вернуть поставщику.

Исходные факты (не пересматриваются):

1. Доход считается по чекам: для предоплаты момент денег — чек предоплаты, для оплаты при получении — чек полного расчёта; возвраты покупателям уменьшают сумму.
2. Деньги, которые Rossko возвращает за возвращённые детали, — не доход.
3. Налог здесь не считается и советов по налогам нет. Даты напоминаний — настройки; сроки сверяйте с банком и ФНС. Подтверждён один срок: налог АУСН платится до 25-го числа следующего месяца.
4. Пункт выдачи получает оплату за операции по договору: ставки — в настройке `contract.rates`, по умолчанию все 0.
5. Реквизиты сторон акта — только из env. Настоящих реквизитов, контактов и токенов в репозитории нет.

Все суммы — целые копейки из записанных строк базы (чеки, платежи, возвраты, позиции заказа по ценам заказа); ничего не пересчитывается по сегодняшним ценам.

## 1. Где что

| Что | Где |
|---|---|

| Операции акта в CSV | `/api/admin/month/csv?m=ГГГГ-ММ` — ссылка «Скачать CSV» (дата, заказ, операция, ставка) |
| Ставки договора | `/admin/month/rates?m=ГГГГ-ММ` — ссылка «Ставки договора» / «Изменить ставки» |

| Склад | `/admin/stock` — «Склад» в меню |

Всё за паролем админки (Basic auth). В демо (`DEMO_MODE`) этих страниц нет — 404.

## 2. Календарь месяца

| День (Екатеринбург) | Что приходит владельцу | Откуда день |
|---|---|---|
| 1-е, 09:00 | «Закрытие сентября 2026: выручка по чекам …, маржа … (…%), операций для акта N, расхождений с ЮKassa: проверить. Отчёт: <ссылка>» | расписание задачи `month-close` |
| 3-е | «Акт для пункта выдачи за сентябрь 2026: проверьте операции и распечатайте — <ссылка на акт>» | `finance.reminder_days.act` (3) |
| 5-е | «Сверьте операции в интернет-банке за сентябрь 2026. Список для сверки — <ссылка>» | `finance.reminder_days.bank_check` (5) |
| 25-е | «Срок уплаты налога АУСН — до 25-го (за сентябрь 2026).» | `finance.reminder_days.tax` (25) |

- Каждое сообщение уходит один раз за месяц: повторный запуск и перезапуск worker ничего не дублируют (ключи `alert:month-close:<месяц>`, `alert:finance-reminder:<вид>:<месяц>`).
- Напоминания проверяются каждый день в 09:10. Если worker был выключен в нужный день, напоминание уйдёт в один из двух следующих дней; позже — уже нет.
- Дни меняются в настройке `finance.reminder_days` (1–28). Хотите напоминание о налоге заранее — поставьте, например, 20.
- **Куда.** В личный чат владельца с ботом продавцов (сотрудник с ролью `owner` и Telegram id). Если такого чата нет или Telegram его не принимает (владелец не нажал Start), сообщение уходит в чат продавцов. Тогда «Закрытие месяца» приходит **без сумм**: «Закрытие сентября 2026: операций для акта N. Отчёт месяца — в админке: <ссылка>». Выручку и маржу видно только в админке.

## 3. «Выручка по чекам»

Чеки, успешно зарегистрированные в месяце (время — событие `receipt_succeeded` в журнале заказа):

| Строка | Что считается |
|---|---|
| Предоплата 100% | чеки предоплаты заказов с предоплатой — сумма их платежа |
| Полный расчёт при получении | чеки оплаты при получении — сумма платежа |
| Возвраты покупателям | чеки возврата — со знаком минус |
| **Итого по чекам** | предоплата + полный расчёт − возвраты |
| Зачёт предоплаты при выдаче | показывается отдельно и в итог не входит: новых денег он не приносит |

Ниже для сверки: возвраты денег, прошедшие в месяце (по `refunds.succeeded_at`), и число выданных заказов.

## 4. «Маржа»

По позициям заказов, выданных в месяце (`orders.handed_at`), по ценам заказа:

маржа = цена покупателю − закупка у Rossko (`price_supplier_at_order`) − эквайринг − доставка Rossko.

- **Эквайринг — оценка**: ставка `finance.acquiring_bp` (по умолчанию 280 = 2,8%) от продажи позиции. Точная комиссия — в реестре выплат ЮKassa; если ваш тариф другой, поменяйте настройку.
- **Доставка** — `delivery_cost` заказа у Rossko, разнесённый по позициям пропорционально закупке.
- Таблица по группам цены (фильтры, тормоза и т. д.) и список **заказов в минус** со ссылками на карточку — с них начинайте разбор.

## 5. Акт для пункта выдачи

Операции месяца считаются из того, что уже записано:

| Услуга в акте | Ед. | Откуда |
|---|---|---|
| Приёмка детали от поставщика | шт. | отметка «Приехало» по позиции (событие `item_arrived`) |
| Хранение заказа | сут. | календарные сутки от приезда заказа до выдачи, отказа или неявки; заказ ещё в точке — до сегодня |
| Выдача заказа покупателю | шт. | «Выдал» (событие `handed_over`) |
| Приём возврата от покупателя | шт. | «Принял возврат» по претензии (`claims.return_accepted_at`) |
| Подбор запчастей по VIN | шт. | отправленное мастером предложение по заявке (`vin_requests.answered_at`) |
| Проверка применимости детали | шт. | ответ мастера по проверке подбора (`fit_checks.answered_at`) |
| Диагностика детали по претензии | шт. | решение по претензии «брак» или «не подошло» (`claims.decided_at`) |
| Обработка заказов: N% от стоимости выданных заказов | усл. | если в договоре есть процент с оборота — от продаж выданных в месяце заказов |

**Ставки.** `/admin/month/rates`: цена каждой операции в рублях, процент с оборота, галочка «Хранение оплачивается по договору» (снята — хранения нет ни в акте, ни в CSV). «Показать акт с этими ставками» — предпросмотр итога акта выбранного месяца «сейчас → станет»; «Сохранить ставки» — с галочкой «подтверждаю», через журнал изменений настроек (`settings_audit`). Ставки одни для всех месяцев: акт любого месяца считается по текущим, поэтому подписанный акт храните у себя.

**Пока ставки не заданы** (все 0), на странице месяца и над печатной формой — «Ставки не заданы»: операции посчитаны, акт выходит на 0 ₽. На бумагу это предупреждение не печатается.

**Печатная форма.** «Акт № 09/2026 от 30 сентября 2026 г. об оказании услуг по договору № … от …», период, исполнитель (пункт выдачи) и заказчик (ИП продавца) с ИНН, ОГРНИП и адресом, таблица «Наименование — Кол-во — Ед. — Цена — Сумма», итог цифрами, строка «Услуги оказаны полностью и в срок…», места для подписей. В акте только услуги и количества — слов о распределении денег в нём нет. Печать — кнопка «Печать» (меню браузера, A4). Незаданные реквизиты печатаются пустыми строками для заполнения от руки, а на экране — подсказка, какие переменные env задать.

**CSV.** Каждая операция строкой: дата (у хранения — день), номер заказа (или «VIN 0192a3b4» / «проверка 0192a3b4», если заказа не было), услуга, ставка. Разделитель `;`, десятичная запятая, кодировка UTF-8 с меткой — открывается в Excel.

## 6. «Сверка с ЮKassa»

Кнопка «Сверить» берёт из ЮKassa все платежи и возвраты месяца (постранично) и сравнивает с базой по ID: сумма и статус. Объекты на границе месяца (создан у нас в 23:59:59, у ЮKassa — в 00:00:01) дочитываются по одному, чтобы не считаться расхождением.

| Расхождение | Что делать |
|---|---|
| Есть в ЮKassa, нет в базе | платёж прошёл мимо сайта или вебхук не дошёл — найти в ЛК ЮKassa по ID, сверить с заказом (runbook 12.7) |
| Есть в базе, нет в ЮKassa | обычно тестовая запись или платёж другого магазина — проверить ID |
| Сумма не совпала | открыть заказ, сверить с ЛК ЮKassa |
| Статус не совпал | «в ожидании» в базе обычно догоняет сверка каждые 10 минут — нажмите «Сверить» позже; осталось — карточка заказа и ЛК ЮKassa (runbook 12.6, 12.7) |

Каждая сверка сохраняется (таблица `finance_reconciliations`: месяц, когда, кто, результат); на странице — последняя. Если ЮKassa не ответила, ошибка показывается и сохраняется вместе с результатом, страница не падает. Без подключённой ЮKassa кнопка неактивна.

## 7. «Не доход (сверить с банком)»

Список денег, которые Rossko вернул в месяце за возвращённые детали («Деньги вернулись»): дата, заказ, деталь, сумма. В выписке банка это возврат оплаты поставщику, а не выручка — отметьте его по правилам вашего банка.

Ниже — постоянный чек-лист сверки с банком: поступления от ЮKassa против реестра выплат, возвраты Rossko из списка, оплаты Rossko и пункту выдачи с понятным назначением, сроки — сверить с банком и ФНС (налог АУСН — до 25-го). Сумм налога и советов здесь нет.

## 8. Возвраты поставщику

Возврат создаётся там же, где и раньше: неявка или отказ при выдаче (`supplier_return_task`), повреждение при приёмке, решение по претензии. Дальше:

```
ждёт сдачи водителю ──«Сдал водителю»──▶ сдан, ждём деньги ──«Деньги вернулись»──▶ деньги вернулись
        │                                        │
        └──────────────«Не берут»────────────────┴──▶ не принят — на складе (себестоимость = закупка)
```

- **В боте продавцов** у карточки заказа строка задачи «Вернуть Rossko до 12 октября: MANN W 914/2 × 1 — «Сдал водителю» или «Не берут»» и две кнопки на каждую деталь. Нажать может любой сотрудник; повторное нажатие и старая карточка ничего не меняют. После «Сдал водителю» строка — «сдан водителю 8 октября, ждём деньги», кнопки исчезают.
- **«Не берут»** — деталь остаётся у нас: запись на складе по закупочной цене заказа (`price_supplier_at_order × кол-во`) с причиной «Не принят поставщиком».
- **Напоминания в чат продавцов** по детали, которая ещё в точке: за 3 дня до срока возврата Rossko (`orders.supplier_return_deadline_at`), за 1 день («Остался последний день…») и после срока («Срок возврата Rossko прошёл…»). Каждое — одно сообщение; после перерыва в работе worker приходит только последнее актуальное.
- **Деньги не пришли за 10 дней** после «Сдал водителю» — одно сообщение владельцу: заказ, деталь, ожидаемая сумма, ссылка на `/admin/returns`.
- **В карточке заказа в админке** остались «Rossko принял возврат» (деталь принята, деньги ждём; с заполненным «Получено, ₽» — то же, что «Деньги вернулись») и «Rossko не принял: на склад» (то же, что «Не берут»).
- **`/admin/returns`**: сначала просроченные, потом с истекающим сроком, остальные по сроку, затем «ждём деньги» (дольше всех ждущие сверху) и закрытые за 30 дней. Кнопки «Сдал водителю», «Не берут», «Деньги вернулись» (сумма из выписки Rossko).
- Автоматическая сверка денег Rossko (`GetSettlements` API Rossko) — фаза 4, когда будут ключи; пока «Деньги вернулись» отмечается руками (в коде оставлено место — TODO в задаче напоминаний).

## 9. Склад

`/admin/stock`: детали, которые Rossko не принял, — себестоимость, причина, дата записи, дата списания. «Списать» (с галочкой «подтверждаю») — деталь больше не числится на складе. Продажа со склада — позже.

## 10. Настройки и переменные

| Настройка (`settings`) | По умолчанию | Что |
|---|---|---|
| `contract.rates` | все ставки 0, процент 0 | `{perOperationKop: {receive, store_day?, handover, return_accept, vin_selection, fit_check, claim_diagnostics}, turnoverBp}`; меняется на `/admin/month/rates` |
| `finance.acquiring_bp` | 280 (2,8%) | оценка эквайринга в марже |
| `finance.reminder_days` | `{act: 3, bank_check: 5, tax: 25}` | дни напоминаний владельцу |

Ставки договора меняются на `/admin/month/rates`. Для двух других настроек отдельного экрана нет — запросом в базе (как другие настройки, runbook 12.4), например:

```sql
update settings set value = '250'::jsonb, updated_by = 'admin', updated_at = now()
 where key = 'finance.acquiring_bp';
update settings set value = '{"act": 3, "bank_check": 5, "tax": 20}'::jsonb,
       updated_by = 'admin', updated_at = now()
 where key = 'finance.reminder_days';
```

Неверное значение не ломает страницы: берётся значение по умолчанию.

| Переменная env | Что |
|---|---|
| `CONTRACTOR_REQUISITES_NAME` | пункт выдачи как в договоре: «ИП Петров Пётр Петрович» |
| `CONTRACTOR_REQUISITES_INN` | ИНН пункта выдачи (10 или 12 цифр) |
| `CONTRACTOR_REQUISITES_OGRNIP` | ОГРНИП (15 цифр) или ОГРН организации (13 цифр) |
| `CONTRACTOR_REQUISITES_ADDRESS` | адрес, необязательно |
| `CONTRACT_NUMBER`, `CONTRACT_DATE` | номер и дата договора (`ГГГГ-ММ-ДД`), дата необязательна |
| `SELLER_REQUISITES_*` | заказчик в акте — реквизиты ИП продавца (уже заданы для сайта) |

## 11. Чего здесь нет

Продажи со склада, автоматической сверки денег Rossko (`GetSettlements`), разметки операций в банке, выгрузок в 1С и расчёта налога. Отдельно — ставки по месяцам: если договор поменяется посреди года, старые акты распечатайте до смены ставок.

## 12. Для разработчика

- Чистая логика: `packages/domain/src/finance.ts` (границы месяца в Asia/Yekaterinburg, строки и итог акта, CSV, маржа, сравнение по ID, тексты сообщений).
- Чтение месяца и сверка: `packages/orders/src/finance.ts` (`loadMonthReport`, `runMonthReconciliation`); возвраты и склад: `packages/orders/src/supplier-returns.ts`.
- Worker: `apps/worker/src/jobs/housekeeping/month-close.ts` (задачи `month-close` 1-го в 09:00 и `finance-reminders` ежедневно в 09:10), `reminders.ts` (напоминания по срокам возврата и 10 дней без денег), кнопки — `apps/worker/src/bots/seller/supplier-returns.ts`.
- Миграция `0010_month_close`: статус `shipped`, `supplier_returns.shipped_at` и `refunded_at`, таблица `finance_reconciliations`, индекс журнала по типу и времени.
- `GET /refunds` ЮKassa (список возвратов с курсором) — по документации; в эмуляции msw он есть, на боевом API формат списка сверить при подключении (VERIFY).
